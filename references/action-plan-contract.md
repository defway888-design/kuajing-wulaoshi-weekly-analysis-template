# 行动建议生成契约

## 1. 唯一职责

行动建议只由周数据分析主 Skill在完成异动识别和诊断后生成。流量和转化率诊断 Skill只提供证据；运营执行端只读取系统建议、填写运营最终方案和保留人工修改记录。

不得让运营端再次读取原始数据或用另一个模型重新生成系统建议。

## 2. 记录唯一性

正式记录键固定为：

```text
报告周期 + 站点 + 店铺 + 负责人姓名 + 父ASIN + 异动指标
```

同一周期、同一记录键只能有一份同规则版本、同批次版本、同内容哈希的系统建议。`流量+转化率异动`保持一个项目，不拆成两份行动方案。

同站点、同店铺存在同名负责人且无法唯一识别时，停止该负责人的在线表格写入与邮件发送，提示老板确认负责人身份；不得猜测归属。

## 3. 行动方案状态

只允许：

```text
正式行动方案
待复核观察
```

`正式行动方案`必须同时满足：

- 异动已确认且属于当期或缓慢高优先异动。
- 诊断完整完成，或可用但有证据缺口。
- 至少有一项可追溯、可核验的可控制因素与对应动作。
- 不存在核心数据冲突或诊断阻断。
- 至少存在一项P0或P1建议。

下列情况必须使用`待复核观察`，不得编造P0/P1：

```text
待复核异动
低样本、从0新增、无历史数据、负责人变更
诊断失败或诊断阻断
核心来源冲突
只有不可控制因素
缺少可控制证据
无法形成明确可执行动作
流量与转化率诊断结论冲突
```

待复核观察仍保留异动事实、证据缺口、观察重点、复核要求、版本和哈希，但`可控制因素`、`可执行动作`、`P0建议动作`、`P1建议动作`留空。

## 4. 生成顺序与证据边界

每条记录按以下顺序生成：

```text
异动事实
-> 证据摘要
-> 可控制因素
-> 可执行动作
-> 不可控制因素
-> 观察记录
-> P0/P1建议
```

没有诊断或数据证据时，不得猜测原因、归因或动作。

可控制因素只包括本店可调整且可验证的事项，例如广告、价格、Coupon/Deals/促销、主图/标题/五点/详情页、库存、配送、可售状态、Buy Box，以及合规的产品体验、售后和评分改善。

不可控制因素只记录和观察，例如季节性、市场需求、搜索趋势、平台流量波动和竞争对手动作。竞品价格动作是观察因素；本店是否调整价格属于可控制动作。不可控制因素不得写成运营人员必须完成的改善承诺。

禁止诱导好评、操纵评论或其他违反平台规则的动作。

## 5. P0/P1动作矩阵

P0表示立即止损或修复：当天确认，通常1至2个工作日内处理。P1表示放量、恢复或验证：通常7天内完成。同一记录可同时有P0和P1。

行动主方向由转化率决定。对于单周期异动，流量绝对变化小于30%、转化率绝对变化小于50%视为“未明显变化”；对于缓慢异动，使用30天后7天对前7天的最终比较值并沿用相同阈值。10%和20%仅用于趋势候选筛选，不能当作行动矩阵阈值。

| 流量变化 | 转化率变化 | 行动原则 |
|---|---|---|
| 上升 | 上升 | P1放大已验证的有效流量 |
| 下降 | 上升 | P1恢复或增加可控制流量 |
| 上升 | 下降 | P0优先转化率止损，暂停无保护的流量放大 |
| 下降 | 下降 | P0先止住转化率下降，再用P1恢复流量 |
| 变化 | 未明显变化 | P1小步流量测试，观察转化率承受能力 |
| 未明显变化 | 上升 | P1测试增加流量 |
| 未明显变化 | 下降 | P0转化率止损 |

转化率止损必须覆盖已有证据支持的主要可控制环节：价格、Coupon/Deals/促销、页面内容、合规产品体验和售后、库存/配送/可售状态/Buy Box。不得因为某一项没有证据就编造该项动作。

## 6. 系统只读字段

在线表格的系统建议区固定写入以下字段。原有16个行动字段保留，新增的异动上下文、六项指标和五项复核字段必须同时写入：

```text
记录键
报告周期
负责人
父ASIN
异动指标
行动方案类型
证据摘要
可控制因素
可执行动作
不可控制因素
观察记录
P0建议动作
P1建议动作
规则版本
批次版本
内容哈希
异动来源
当前比较窗口
基准比较窗口
当前流量值
基准流量值
流量变化率
当前转化率
基准转化率
转化率变化率
后续复核指标
评价基准值
预期改善方向
建议评价时间
评价口径说明
在线记录哈希
批次聚合哈希
```

`后续复核指标`、`评价基准值`、`预期改善方向`、`建议评价时间`和`评价口径说明`均为系统只读字段。正式行动方案全部必填；待复核观察至少必须填写复核指标、建议评价时间、评价口径说明，评价基准值取到可靠数据时填写，否则写`未获取`，预期改善方向写`待复核后确定`。

六项流量/转化率字段对每条异动都必须填写，因为行动主方向需要同时判断两类指标。未命中的指标也要写入同窗口真实变化；确实无法计算时写`未获取`并将该记录降为`待复核观察`，不得留空或猜测。

运营人员手工填写的最终方案、采纳状态、完成情况和备注属于下游人工区。主 Skill不得覆盖该区域。

## 7. 版本与哈希

每条建议必须有三类哈希：

```text
内容哈希：原有16个行动字段的系统建议内容
在线记录哈希：全部系统只读字段
批次聚合哈希：按记录键排序后的 在线记录哈希 集合
```

同记录键、同规则版本、同批次版本且内容哈希相同：跳过重复写入。

同记录键、同规则版本、同批次版本但内容哈希不同：视为异常，停止该记录写入并提示人工核查。

规则版本或批次版本变化：新增一条系统记录，旧记录标记`已替代`，不得覆盖运营人员手工字段。邮件发送前只发送本批次最新版本；邮件发送后出现更新，必须另发更新邮件。
