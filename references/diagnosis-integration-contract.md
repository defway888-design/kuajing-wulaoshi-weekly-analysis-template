# 高优先级诊断对接契约

## 1. 触发范围

只有 `最终状态 = 高优先级异动` 的父 ASIN进入深度诊断。`当期高优先异动`和`缓慢高优先异动`都必须进入。

按异动指标严格调度：

| 异动指标 | 必调诊断 |
|---|---|
| 流量异动 | 仅调用流量异动诊断 Skill |
| 转化率异动 | 仅调用转化率异动诊断 Skill |
| 流量+转化率异动 | 同时调用两个诊断 Skill，并生成一份父 ASIN综合报告 |

除`流量+转化率异动`外，禁止为了“更完整”而额外调用另一个诊断 Skill。

## 2. 上游输入

主 Skill 每次调用必须传入并在报告中保留：

```text
记录键
报告周期
站点
店铺
负责人
父ASIN
商品名
异动指标及方向
异动来源：单周期异动 / 30天双窗口趋势异动
当前比较窗口
基准比较窗口
当前流量值 / 基准流量值 / 流量变化率
当前转化率 / 基准转化率 / 转化率变化率
报告时区
高优先级类型
```

流量诊断只使用流量相关输入；转化率诊断还应接收同记录键、同窗口、同父 ASIN下可取得的全部子体`sessions_total`与`volume`汇总，用于贡献拆解。不得在诊断端自行改写报告窗口、回退到默认月份或猜测指标方向。

## 3. 同源证据返回

每个诊断 Skill返回的运营可读报告、Word报告和结构化证据必须来自同一次诊断、同一个内部证据对象。主 Skill不得解析Word或自然语言报告后重新生成证据、原因或行动建议。

结构化证据的固定字段为：

```text
记录键
父ASIN
异动指标
异动方向
因素编码
因素名称
当前期证据
对比期证据
数据来源
证据状态
证据缺口
诊断结论
```

流量+转化率异动保留一个父 ASIN项目和一份综合Word报告；两个诊断的结构化证据按指标分别保留，并在同一`记录键`下合并给行动建议流程。

## 4. 状态映射

诊断 Skill返回状态映射到诊断索引：

| 诊断返回 | 诊断状态 | 核心诊断状态 | 诊断附件可发送 |
|---|---|---|---|
| 完整完成 | 已完成 | 完整完成 | 允许发送 |
| 可用但有证据缺口 | 部分完成 | 可用但有证据缺口 | 允许发送 |
| 诊断失败 | 诊断失败 | 阻断失败 | 禁止发送 |

单个 ASIN诊断失败时：

- 保留异动明细、负责人BI、异动明细BI和诊断索引行。
- 不生成虚构Word报告，不生成正式行动方案。
- 为该记录生成`待复核观察`，原因写`诊断失败，需人工复核`。
- 其他 ASIN、其他负责人和老板包继续处理。

`可发送状态`只表示该ASIN的诊断附件是否允许发送，不得作为整批邮件是否发送的唯一闸门。

## 5. 诊断索引扩展

在原有诊断索引字段后新增：

```text
异动来源
当前比较窗口
基准比较窗口
当前流量值
基准流量值
流量变化率
当前转化率
基准转化率
转化率变化率
行动方案状态
在线表格写入状态
在线表格地址
```

诊断索引、异常明细、行动建议、在线表格和邮件内容必须使用相同的记录键和窗口字段。
