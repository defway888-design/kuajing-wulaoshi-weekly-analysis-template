# 在线表格写入与邮件投递契约

## 1. 生效范围

所有存在异动的负责人都需要在线表格链接，包括只有`待复核观察`的负责人。没有任何异动的负责人不写表格、不发负责人邮件。

首次手动运行完成异动分析后，只向存在异动的负责人逐一收集：

```text
负责人姓名
站点
店铺
收件邮箱
行动方案在线表格链接
```

新增负责人、邮箱变更、表格链接变更或负责人重新出现时，只提示该负责人重新配置。离职负责人保留历史记录，不再写入或发送。

建议将信息保存在运行环境的`owner_delivery_map.csv`，至少包含：

```text
owner_name
site
store
email
table_url
platform
mcp_connection_status
authorization_status
active
first_seen_at
last_seen_at
remark
```

不得把邮箱密码、MCP密钥、OAuth令牌或任何授权凭据写入表格、日志、Skill、GitHub仓库或聊天记录。

## 2. 表格归属与平台识别

每个负责人必须使用唯一在线表格链接；同一链接不得配置给不同负责人。已有表格中的系统记录必须与目标负责人匹配。多个负责人共同负责同一个ASIN时，分别写入每位负责人的独立表格。

支持的首期平台：

```text
飞书多维表格或电子表格
腾讯文档表格
Google Sheets
Microsoft Excel Online
WPS在线表格
```

从表格链接自动识别平台，检查当前Codex环境中对应平台的MCP是否可用，并检查授权、读取、查找或创建区域、追加、按记录键更新、读回校验和文本安全写入能力。

平台MCP未连接、授权失效、权限不足或缺少上述关键能力时，阻断该负责人写入和邮件发送，提示老板完成该平台MCP连接或授权；不得用浏览器模拟点击、复制粘贴或其他平台替代。

## 3. 写入规则

老板端负责创建或定位每位负责人的系统建议区、待复核观察区和字段说明区，并在邮件发送前写入系统只读字段。在线表格采用长期表结构，按新报告周期追加。

同一批次重跑时按记录键更新系统建议区，不重复插入；不得覆盖人工区。写入完成后必须读回校验记录键、规则版本、批次版本、内容哈希和在线记录哈希。

写入失败的自动重试间隔固定为：

```text
第1次：1分钟
第2次：5分钟
第3次：15分钟
```

三次失败后仅阻断该负责人，状态写`表格写入失败，需人工处理`。其他负责人、老板包和已完成负责人的邮件继续。

## 4. 邮件规则

负责人邮件正文必须包含：

```text
报告周期
负责人
高优先级异动数
正式行动方案数
P0建议数
P1建议数
待复核观察数
诊断失败数
在线表格链接
规则版本
批次版本
批次聚合哈希
在线表格写入和读回状态
```

负责人附件只包括：本人异动明细表、本人异动明细BI，以及本人高优先级ASIN Word诊断报告。报告较少且未超阈值时逐个附加；报告较多或超阈值时压缩为该负责人的诊断报告压缩包。`待复核观察`和诊断失败不附虚构报告。

不得再发送`行动方案建议表_<负责人>.csv`。在线表格是行动方案的正式载体。

老板完整包增加系统行动建议审计快照、负责人表格链接和写入状态；轻量包增加行动方案数量和方向汇总、表格写入状态及诊断摘要页。无需在BI增加行动方案模块。

固定生成本地审计文件：

```text
系统行动建议审计快照.csv
负责人在线表格投递状态.csv
```

`负责人在线表格投递状态.csv`固定字段：

```text
报告周期
站点
店铺
负责人
收件邮箱
在线表格地址
平台
MCP连接状态
授权状态
写入状态
回读状态
重试次数
失败原因
邮件发送状态
最新验证时间
```

每个当期存在异动的负责人必须有且仅有一行投递状态。该文件只进入老板包和运行审计，不进入其他负责人的附件。

## 5. 批次、发送和异常隔离

批次状态只允许：

```text
完成：所有有异动负责人均已完成诊断、行动生成、表格写入读回和发送。
部分完成：至少一位负责人完成，且至少一位负责人因诊断、表格、配置或发送失败未完成。
失败：核心数据、核心校验或老板包生成失败，无法形成可用批次。
```

周一00:00开始处理，09:00为最早正式发送时间；09:00未完成时，完成验证后立即发送。已完成负责人和老板包可以先发送，失败负责人恢复成功后单独发送补发邮件。

自动发送只在老板明确授权后开启，并从授权后的第一个周一生效。试运行模式允许重复手动执行，不创建自动化也不自动发送正式邮件。
